# `assets/sce_sys/` — PS Vita VPK and LiveArea assets

This directory contains the `sce_sys` resources packaged into the PSVitaAlive VPK. These files are part of the client build contract and should not be moved or renamed without updating CMake and validating the resulting VPK on Vita3K/real hardware.

## Current structure

```text
assets/sce_sys/
├── icon0.png
├── pic0.png
└── livearea/
    └── contents/
        ├── bg0.png
        ├── startup.png
        └── template.xml
```

When packaged, the directory becomes:

```text
sce_sys/
├── icon0.png
├── pic0.png
└── livearea/
    └── contents/
        ├── bg0.png
        ├── startup.png
        └── template.xml
```

`param.sfo` and `eboot.bin` are generated by the build system and are not stored here as source assets.

## Image contract

The current validated assets use these dimensions and PNG characteristics:

| File | Resolution | Current format |
|---|---:|---|
| `icon0.png` | 128×128 | 8-bit indexed PNG with alpha |
| `pic0.png` | 960×544 | 8-bit indexed PNG, up to 256 colors, with alpha |
| `bg0.png` | 840×500 | 8-bit indexed PNG with alpha |
| `startup.png` | 280×158 | 8-bit indexed PNG with alpha |

The important rule is to preserve the exact resolution and use a Vita-compatible indexed PNG format. `pic0.png` was explicitly quantized to a maximum of 256 colors with `pngquant` during the validated setup.

## `template.xml`

The current LiveArea template references the background and startup images:

```xml
<livearea style="a1" format-ver="01.00" content-rev="1">
  <livearea-background>
    <image>bg0.png</image>
  </livearea-background>
  <gate>
    <startup-image>startup.png</startup-image>
  </gate>
</livearea>
```

Do not rename `bg0.png` or `startup.png` without changing the XML accordingly.

## Build integration

The VPK is built explicitly with `vita-pack-vpk` rather than relying on `vita_create_vpk()` for these resources. The current CMake command maps:

```text
../assets/sce_sys  →  sce_sys
```

This relative mapping is intentional because the repository's local client directory is named `Client PSVitaAlive` and contains a space. The command is executed from the build directory with `VERBATIM` enabled.

The VPK target also depends on `eboot.bin-self`, which produces the `eboot.bin` payload required by the package.

## Validation checklist

Before committing a LiveArea change:

1. Verify image dimensions.
2. Verify the PNG is indexed/8-bit as required by the current asset contract.
3. Remove accidental Windows metadata files such as `*:Zone.Identifier` from the asset tree.
4. Run a clean CMake build.
5. Run `unzip -l PSVitaAlive.vpk` and verify the package contains the expected `sce_sys` files only.
6. Install the VPK on Vita3K and, when possible, real hardware.
7. Confirm the icon, LiveArea background and startup image visually.

Do not add editor metadata, source backups or `Zone.Identifier` files to the VPK asset tree.
