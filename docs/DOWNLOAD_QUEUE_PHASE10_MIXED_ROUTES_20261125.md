# Mixed routes and system boundary

All selected group destinations are resolved once before admission. Typed Game/Data ZIP, ZIP-backed VPK, plugin, known PSP formats and opaque filenames use the queue's existing native format detection and validation. Opaque routes and uncertain conversion are tail barriers; imc0/xmc0 are probed if relevant, and unavailable mounts fail closed. A group may contain one BGDL handoff. The OS handoff never counts as installed; when it occurs before additional components, the core records a partial report and moves untouched tail components to persistent recovery. A failed BGDL step stops dependent work. The deferred tail can be explicitly reselected from the same current catalog after OS installation, with a local app marker plus the user's confirmation; changed metadata, missing app, custom destinations, unsafe routes and plugin directives require manual review. The app marker alone does not prove the OS task or version completed. No OS task polling/cancellation API has been verified, no automatic dependent work is launched, and no system installation completion is claimed. Queue recovery schema PSQR2 reads PSQR1. HTTP staging-reset events are opt-in for download manager only. Native and physical tests pending.
