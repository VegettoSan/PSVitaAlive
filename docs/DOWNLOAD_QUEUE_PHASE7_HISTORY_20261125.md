# Download queue — bounded persistent history

The idle download manager now displays the latest 40 terminal job records and their component outcomes, catalog identity, version and system-clock date. Live jobs and the final session report still use the original Session. History cannot launch, cancel, retry or resume anything. The record intentionally excludes URLs, zRIF, plugin directives, paths, raw results and worker metadata. Two alternating checksummed snapshots in ux0:data/psvitaalive/queue_history.a/.b preserve the previous valid slot after an interrupted write. Reads are bounded to 32 KiB per slot; writes occur only on lifecycle events when no step owns the native controller. No per-frame filesystem I/O. This is history, not persisted pending queue recovery. The 40-record limit and display-only format are conservative implementation decisions pending device validation. Host tests cover encoding, privacy, terminal-only capture, dedup, bounded size and torn-write fallback. Native build and real-device results are not yet confirmed.
