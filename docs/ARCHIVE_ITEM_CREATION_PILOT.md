# Automatic initial Archive.org preservation — VitaForge pilot

Integrated directly on main. The existing owned-item VPK batch keeps its normal scope and schedule. The new module inventories canonical apps without archive references, but only VitaForge v0.1.15 is authorized to create a new item in this pilot. The initial push and subsequent scheduled/manual runs attempt or reconcile the pilot under the existing catalog-publisher lock.

Proposed item: psvitaalive-vitaforge; public title: VitaForge; creator: josephinoo. Description from canonical application; PSVitaAlive attribution and source references. The current VPK digest is pinned to the official release. Icon and screenshots are optional and deduplicated by URL/content. No Game Files, Data Files, DLC or plugin transfers. Existing exclusion policy remains honored; no new catalog license/SPDX gate.

The module checks the historical log, relevant canonical URLs, exact identifier metadata and Archive advanced search before initial creation. Any ambiguity or failed query prevents creation. A durable per-file checkpoint in data/archive_item_creation_jobs.json precedes every PUT. Uncertain writes are never repeated automatically. After ownership, metadata size/MD5 and complete public SHA-256 verification for all files, it commits the individual app JSON and historical CSV together with the completed checkpoint. Generated catalogs remain exclusively owned by validate.yml. Future VPK updates use the existing owned-item batch.

Report: archive-backup-batch-report/new-items.json. DISCOVERY_REQUIRED means no local archive reference, not proven absence from Archive.org. All other candidates are inventory only until the pilot is verified and explicitly expanded. Supported pilot artwork is limited to the pinned upstream GitHub raw host. If a checkpoint is stuck, inspect the Archive manifest before any manual reset; never blindly retry PUT. The public item and real transfer require Actions and configured secrets; a commit alone is not proof of creation.

## Ownership-aware discovery

Search now returns public item identifiers, not just a count. The exact proposed identifier must be free. Each search hit is checked via item metadata against the configured uploader; an alternate owned item, unknown owner, missing metadata or exact identifier collision stops creation. Unrelated or third-party hits are reported but never written to, and do not prevent a new owned preservation item with a free identifier. Workflow logs and job summary include safe categorical diagnostics, never uploader email or keys.

## Identifier fallback and account-scoped discovery

The global search previously returned too many results. Search is now scoped to the configured uploader and actual metadata ownership is still checked. Exact identifiers are independently checked before creation. Four deterministic options are available: `psvitaalive-vitaforge`, `psvitaalive-vitaforge-psvita`, `psvitaalive-vitaforge-homebrew`, `psvitaalive-vitaforge-archive`. All four are inspected for existing owned items before the first free option is selected. Unknown ownership, unavailable metadata or all occupied options stop safely. Once a PUT checkpoint exists, its chosen identifier is fixed; no fallback is allowed after an uncertain transfer. The actual identifier is written to the historical CSV on completion. Public title and Title ID do not change.
