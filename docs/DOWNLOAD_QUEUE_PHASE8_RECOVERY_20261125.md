# Download queue — durable recovery checkpoint

The checkpoint records pending and interrupted job identities (not runnable requests) in two alternating, checksummed files. Admission is persisted before returning success; a main-thread pre-start hook writes the Running identity before any native dispatch. If the write fails, the group is aborted before a worker can launch. Terminal records leave the checkpoint; history is independent. At restart the existing orphan-download cleanup remains authoritative. There is no automatic replay and no claim of byte-level resume across process death.

The idle manager offers a recovery view and explicit restore/discard confirmation. Initial restoration is deliberately limited to untouched, known-size internal Homebrew jobs with no license, plugin directives, system handoff, uncertain destination or saved ZIP. It matches exact current catalog identity/version/revision and one unique link fingerprint, re-plans the group and uses the existing admission/space protections. Custom ZIP destinations must be reselected manually; interrupted, unsupported and changed-catalog records are shown for manual review, never automatically executed. Fingerprints are noncryptographic matching hints, not authentication. No URLs, zRIF, paths, backend tokens or plugin directives are serialized. The combined unresolved/live record count cannot exceed the existing 100-job limit. Tests cover interrupted state, terminal removal, privacy, identity changes, corrupt record rejection and pre-start write failure. Physical-device validation and full mixed-route recovery are still required; no main/release/catalog changes.
