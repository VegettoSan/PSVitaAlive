# `web/` — PS Vita Alive Store website

The website is a static HTML/CSS/JavaScript application deployed through GitHub Pages. It has no custom backend and does not edit catalog data.

## Data contract

The website consumes the generated Homebrew catalogs:

```text
catalog.json
authors.json
categories.json
```

The files are generated by GitHub Actions.

```text
canonical data + external sources
            ↓
       GitHub Actions
            ↓
 generated catalogs
            ↓
       web/*.html
       web/js/*.js
```

## Public data URLs

The website can load the same public catalog directly from raw GitHub:

```text
https://raw.githubusercontent.com/VegettoSan/PSVitaAlive/main/catalog.json
https://raw.githubusercontent.com/VegettoSan/PSVitaAlive/main/authors.json
https://raw.githubusercontent.com/VegettoSan/PSVitaAlive/main/categories.json
```

Do not hard-code duplicated application data into the website when it already exists in the catalog.

## Main features

The current website structure supports:

- application browsing;
- author browsing and profiles;
- categories and subcategories;
- application screenshots and icons;
- multiple download sources;
- version and release date information;
- search and sorting;
- game catalog views where the corresponding generated game catalogs are used.

## External URLs

Images and downloads coming from external sources must be absolute, valid public URLs. The website must not assume that a relative VitaDB/VitaDBtoo path exists inside GitHub Pages.

## Fallbacks

UI components should tolerate unavailable icons, avatars and screenshots. The catalog pipeline provides fallbacks where possible, but the frontend should still protect against broken remote resources.

Author fallback:

```text
https://raw.githubusercontent.com/VegettoSan/PSVitaAlive/main/authors/icon/autoricon.png
```

Application icons may fall back to the corresponding category icon when the primary resource is unavailable.

## Development rules

When changing the website:

1. Keep the generated catalog contract stable.
2. Do not change JSON field names without updating the catalog pipeline and PS Vita client.
3. Test application, author and category pages.
4. Test multiple authors and multiple links.
5. Verify external downloads and media URLs.
6. Check cache/update behavior after a catalog rebuild.
7. Preserve compatibility with older application records and optional fields.

## GitHub Pages

Deployment is automated through `.github/workflows/pages.yml`. No custom web server is required.
